SITE-WIDE FUNCTIONALITY AUDIT + POLISH — SAATH WEBSITE

IMPORTANT:
This is a FUNCTIONALITY TEST and bug-fixing task, NOT a visual redesign.

Audit the ENTIRE Saath website, page by page and interaction by interaction.

The goal is to make the website fully functional, consistent and polished while preserving the existing visual design exactly as much as possible.

DO NOT redesign the website.

==================================================
STEP 1 — AUDIT THE ENTIRE WEBSITE
==================================================

Systematically inspect EVERY page and EVERY interactive element.

Test all existing:

- Navigation links
- Header links
- Navigation menu items
- Buttons
- Text-based buttons
- Text links
- Image links
- Cards that are intended to be clickable
- Campaign links
- Curriculum/document links
- “Read Our Story” links
- “Explore the Campaign” links
- Newsletter links
- Instagram link
- Email link
- Any back buttons
- Any forward/navigation buttons
- Any page-to-page transitions
- Any interactive elements
- Any hover/click states
- Any mobile navigation interactions

Do not assume that something works simply because it looks like a button.

Actually verify its destination and behaviour.

==================================================
PAGES TO TEST
==================================================

Audit every page currently present in the Saath website, including at minimum:

1. HOME

STEP 2 — FIND DUMMY OR BROKEN INTERACTIONS
==================================================

Identify every interactive-looking element that:

- Does nothing when clicked
- Links to an empty page
- Links to a placeholder
- Links to the wrong page
- Uses a dummy URL
- Has an unfinished interaction
- Leads to a non-existent destination
- Has an incorrect navigation target
- Opens the wrong document
- Has a broken back/navigation path
- Looks like a button but is not actually interactive when it should be

Pay particular attention to text-only buttons because they may not have obvious visual boundaries.

Examples include:

“Read Our Story”

“Explore the Campaign”

“Read the Newsletter”

“View Report”

“View Curriculum”

Instagram

Email

Campaign/documentation entries

Any navigation links

==================================================

Check all external links.

If a required external destination genuinely does not exist, DO NOT invent one.

Instead, leave the element unchanged and report the issue rather than fabricating a destination.

==================================================
STEP 5 — FIX FUNCTIONALITY ERRORS
==================================================

After identifying problems, fix all MINOR and CLEAR functionality errors automatically.

Examples:

- Broken internal links
- Incorrect page destinations
- Buttons that should navigate but don't
- Incorrect navigation targets
- Missing click interactions
- Broken back buttons
- Incorrect document links
- Text links that should be clickable
- Obvious placeholder/dummy links
- Broken mobile navigation
- Interactive elements with incorrect hitboxes
- Links that accidentally point to the wrong page

When fixing an interaction, preserve the existing visual appearance.

The user should not notice a visual redesign.

==================================================
STEP 6 — DO NOT INVENT CONTENT
==================================================

If an interaction points to content that does not exist yet:

DO NOT invent content.

DO NOT create fake statistics.

DO NOT create fake campaigns.

DO NOT create fake documents.

DO NOT create fake URLs.

DO NOT create placeholder information and pretend it is finished.

If the issue is genuinely dependent on missing content or an unavailable external resource, leave it alone and flag it for review.

==================================================
STEP 7 — VISUAL REGRESSION CHECK
==================================================

After fixing functionality, check that the fixes have NOT caused visual problems.

Verify:

- No elements overlap
- No buttons have unexpectedly changed size
- No text has moved unnecessarily
- No images have disappeared
- No sections have been deleted
- No spacing has been broken
- No mobile layouts have been damaged
- No desktop layouts have been damaged
- No typography has changed
- No colours have changed
- No animations have been unintentionally altered

Functionality improvements must preserve the existing Saath design.

==================================================
STEP 8 — MOBILE TEST
==================================================

Perform the same functionality audit on mobile/responsive layouts.

Pay particular attention to:

- Hamburger/navigation menu
- Text links
- Buttons
- Document cards
- Campaign files
- Curriculum books
- Instagram link
- Email link
- Back/navigation controls
- Touch targets

Make sure clickable areas are sufficiently large for touch interaction without visually resizing the buttons.

==================================================
STEP 9 — DO NOT MAKE MAJOR CHANGES
==================================================

If you encounter a MAJOR issue that would require:

- Redesigning a page
- Rebuilding a major component
- Changing the site's visual identity
- Replacing existing content
- Creating a completely new page
- Changing the information architecture
- Rewriting existing copy
- Replacing an existing interaction with a fundamentally different one

DO NOT make that change automatically.

Instead, leave the existing implementation intact and flag the issue for me.

Only make straightforward, low-risk functionality corrections automatically.

==================================================
STEP 10 — FINAL QUALITY CHECK
==================================================

At the end, perform one final pass through the entire website as if you were a first-time visitor.

Start from Home and follow the website naturally.

Check whether a visitor can:

- Understand the navigation
- Open the Saath story
- Navigate to What We Teach
- Navigate to Our Impact
- Open Documentation
- Open Campaign 01
- Open the relevant curriculum/lesson-plan documents
- Return to the main pages
- Open Instagram
- Send an email
- Navigate through every available page
- Use the website comfortably on mobile

The final website should feel like a COMPLETE, REAL, FUNCTIONAL WEBSITE rather than a visual prototype.
